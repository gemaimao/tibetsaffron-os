# BCOS 全系统审计报告（2026-09-12）

> **BRAND CONTENT OS · READ-ONLY AUDIT**  
> **核心定论**：官网只是出口，知识资产才是整个系统的底座。

---

## 审计结论概述

项目已具备官网、知识库工作台、移动录入与公告展示的代码基础；但数据、审核、证据和发布尚未形成统一闭环，不能据此认定为已完成的品牌内容操作系统。

- **纳入审计系统**：4 个业务系统
- **本地数据库资产记录**：7 条
- **前台证据卡 / 原子事实**：9 / 11
- **硬编码公告条目**：6 条

---

## 01｜分类原则澄清

- **官网五段**：访问者的叙事顺序（缘起 → 风土 → 四季 → 劳作 → 产物）。
- **知识库五模块**：资产管理分类（COM 传播、KNO 知识、VIS 视觉、DAT 数据证据、BRD 品牌）。
- **原则**：不应把知识库五模块改成官网五段。应当增加章节、季节、内容用途等映射，让同一条知识资产支持官网、认知文章、新闻通稿和公告。

---

## 02｜四个系统现状与缺口

1. **官网**：已有展示，但此前偏科学论证与检测讲解，不是权威五段结构，创始人、团队、全年劳作不成主线。
2. **知识库 OS**：已有工作台与资产 CRUD；原 `/os` 开发路由重写错位，版本/关系/发布断接已修复。
3. **录入系统**：具备落盘代码，但服务端权限、文件大小/类型限制与肖像授权流程仍需逐步完善。
4. **公告系统**：原仅为数组展示，缺少审批、撤回、有效期和原件引用。

---

## 03｜优先问题与整改（P0 / P1）

- **P0·发布前阻断**：
  - 取消业务写入中自动触发的 `git add/commit/push` 及 shell 注入隐患。
  - 清理代码中硬编码的模型访问密钥，转入服务端环境变量。
  - 公开导出（NotebookLM）增加严格白名单，草稿与禁止声明绝不外泄。
- **P0·内容可信**：
  - 治理元数据结构错位修复，缺失时归为待核验 `UNVERIFIED_PENDING`，严禁推定为真。
  - 显式拦截 `FORBIDDEN_ASSERTION` 禁用断言。
  - 真实断言回归测试，替换固定返回 true。
- **P1·功能断接**：
  - 补齐 API 层缺失的方法（版本恢复、关系维护、模块管理、导出）。
  - 修复 `releaseManagerView` 与 `relationGraphView` 缺失 `store` 导入问题。
  - 纠正仪表盘 fallback 假数据。
