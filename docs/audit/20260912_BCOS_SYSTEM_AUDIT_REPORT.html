01｜先明确：两套“五”不是同一套分类

官网五段是访问者的叙事顺序：缘起 → 风土 → 四季 → 劳作 → 产物。

知识库五模块是资产管理分类：COM 传播、KNO 知识、VIS 视觉、DAT 数据证据、BRD 品牌。

不应把知识库五模块改成官网五段。应当增加章节、季节、内容用途等映射，让同一条知识资产支持官网、认知文章、新闻通稿和公告。

03｜优先问题：先保障可信与可用，再重构首页

P0 · 发布前阻断 服务端权限与自动推送边界

  • OS 校验是浏览器内的固定口令与 localStorage 遮罩；src/main.js:29–47 调用校验后仍继续初始化。开发 API 在 vite.config.js:177–395 未见服务端鉴权。
  • vite.config.js:101–105, 329, 356 在资产写入后执行整仓 git add .、commit、push。提交消息含用户标题并经 shell 拼接，存在命令注入风险；整仓暂存也可能带入不相关改动。此处仅静态识别，未尝试利用。
  • 发现代码内置模型访问密钥：vite.config.js:413–419。不在报告中复述。应由负责人轮换/撤销并迁入服务端密钥配置；仅删当前代码不足以消除历史泄露。
  • scripts/sync-notebooklm.js:24,45–50 只排除 Archived，将其余内容写入 public/notebooklm.md，因此未来 Draft/Review 也会进入可公开分发文件。本次数据库 7 条均为 Published，不能据此断言已经泄露草稿。

建议：建立服务端登录与角色授权；取消业务写入中的自动 Git 推送；公开导出采用“已批准 + 允许公开”白名单；媒体与内容输出实施校验和转义。

P0 · 内容可信 通稿的治理标签比实际门禁更完整

  • 界面调用的是 generateV22Article，没有接到 V2.3 的 generateContentAssemblyPlan。前者只是取前 5 条素材拼标题与摘要。
  • 公开输出的底层生成函数会接受 Draft 输入；虽然界面默认只勾选 Published/VERIFIED，函数自身并不阻断。
  • V2.3 对 FORBIDDEN_ASSERTION 只读取标签，没有拒绝逻辑。治理元数据缺失时，还会推定为品牌自有、当前、确认事实。
  • 数据库 7 条记录中，6 条 ownership/temporal/claim_control 是字符串，1 条缺失；引擎却按嵌套对象读取。这种结构错位会落入默认推定。
  • V2.2“回归测试”直接返回全部 true，并没有执行测试。弹窗还默认填入活动、嘉宾和讲话，并默认 PUBLIC；这些必须改成待补/未确认，不能自动成为事实。

证据：src/components/pressReleaseModal.js:20–47,103–110,210–215；src/services/exportEngine.js:155–168,197–255,371–415。另有重复 class 属性，输出模式按钮事件绑定存在失效风险，尚未浏览器验证。

P1 · 功能断接 工作台版本、关系、发布未完成迁移

src/services/api.js:166–185 的版本返回固定 v1.0、关系返回空数组、发布返回固定记录。与此同时 store.js 在 localStorage 中另有资产、历史、关系、发布实现，尚未与 JSON 数据库统一。

资产详情调用 restoreAssetVersion / createRelation / deleteRelation / exportAssetMarkdown / exportAssetJSON，但当前 api 对象没有这些方法；发布与模块管理也存在未定义 API 调用。releaseManagerView.js:28 使用 store 却未导入；relationGraphView.js:14 同样需要检查并补齐依赖。

API 故障时仪表盘还会显示固定“14 条资产、12 条发布”等成功数据，而当前磁盘数据库只有 7 条。应显示离线/失败状态，不应伪装成功。

证据：api.js:32–44,84；assetDetailView.js:212–256,418；releaseManagerView.js:7–28,122,151；moduleManagerView.js:72,90。
