# Description

VIS-0000 是 Brand Content OS (Sprint-4) 的视觉图谱中枢规范。

自 v0.1.0 起，Visual Module 不再按传统的“图表格式（如流程图、地图、结构图）”进行物理归类，而是统一升级为：
**Knowledge Visualization System (KVS)**。

每一张视觉图谱（VIS Asset）都必须是对某一项/某一类核心品牌知识（KNO Asset）的视觉化映射。

---

# Architecture

VIS 架构与 KNO (Knowledge Module) 保持强映射关系。
整体分为 8 个核心图谱体系：

- **VIS-1000**: 本体认知图谱 (Ontology Visualization)
- **VIS-2000**: 生命科学图谱 (Life Science Visualization)
- **VIS-3000**: 生态风土图谱 (Ecology Visualization)
- **VIS-4000**: 农业科学图谱 (Agriculture Visualization)
- **VIS-5000**: 品质形成图谱 (Quality Visualization)
- **VIS-6000**: 产业认知图谱 (Industry Visualization)
- **VIS-7000**: 文明文化图谱 (Civilization Visualization)
- **VIS-8000**: 未来认知图谱 (Future Visualization)

# Template Design

任何后续新增的 VIS 资产（如 VIS-1000 等），都必须采用以下标准的 Template 结构：

## Metadata 层
包含所有标准字段（ID, Title, Module, Version, Status, Owner, Tags, Created At, Updated At）。

## Mapping 层
必须明确使用 `Reference` 指向对应的 KNO ID 或 DAT ID，确立视觉元素的“事实来源”（SSOT）。

## Visual Elements 层
描述该图谱需要展现的核心要素、层级、节点关系和视觉指引（非具体设计文件，而是视觉逻辑蓝图）。

## Asset Repository 层
记录最终设计源文件（如 Figma / AI / PSD 文件）与输出成品（PNG / SVG / WebP）在 `Assets/` 目录中的存储路径索引。

---

# Development Rules

1. **No Data Invention**: 视觉资产不产生新数据，所有数据与事实只能从 `DAT` 或 `KNO` 引用。
2. **Metadata First**: 即使设计文件尚未完成，也必须优先建立 Markdown Asset 并标记为 `Draft` 或 `In Progress`。
3. **Graph Ready**: 视觉资产的关系必须支持后续引入 Neo4j 或 GraphRAG 的映射需求。
